# qualitest-demo AI 测试流自然语言提示集

本文档提供 **自然语言业务意图**，供在质衡（qualitest）测试流画布的 **AI 设计助手** 中使用。将「加载场景 + 提示正文」一并粘贴到对话框，AI 检索已上传接口、编排节点并补充断言。

## 使用方式

1. **先准备数据**：在靶场管理端「测试场景」页，或调用 `POST /web/test/scenario/load/{场景ID}`，加载每条提示上方标注的场景（默认会先 reset 再写入场景数据）。
2. **再粘贴提示**：把该条的 **加载场景**、**提示正文** 一起发给 AI 设计助手。
3. **AI 负责**：选接口、串联请求、提取变量、设计断言；**不必在提示里写 URL**。  
   - **同流只登录一次**（或挂登录子流），后续步骤复用 `flow.token` / `flow.adminToken`，勿逐步再登录。  
   - 客户端登录 extract 多为 `$.data.token→token`；管理端 `/login` 多为 `$.token→adminToken`。  
   - 勿再写「开启会话保持 / useRunSession」（已废弃）。

确保本流具备客户端登录态后再执行后续业务：若 `flow.token` 已有则跳过登录；否则用主测号登录并 extract `$.data.token→token`；同流只登录一次。

## 编写原则

| 写入提示正文（AI 测不到） | 交给 AI（不必写死） |
|---|---|
| 加载哪个场景 | HTTP 路径与方法 |
| 登录手机号、管理端账号 | 逐步接口调用顺序 |
| 停用账号、SPU/SKU/券 ID、库存、余额等预制状态 | 除场景给定外的字段枚举字面量 |

## 一、认证与账号

### 1.1 客户端登录

**加载场景**：基线 seed（`reset` 或 `01_base_seed` + `02_account_seed`，无需 S/F 场景）

```
客户端 13800000001 / Test@123456 登录。登录成功后查询个人资料，确认手机号为 13800000001（开头登录一次即可，后续用 token）。
```

### 1.2 客户端注册

**加载场景**：基线 seed 即可（`13800000099` 未在 seed 中；若已注册过需先 `reset` 再测）

```
匿名注册新用户，手机号 13800000099，密码 Test@123456，昵称「AI测试用户」。用返回的凭证查询资料，确认注册成功且手机号为 13800000099。
```

### 1.3 管理端登录

**加载场景**：基线 seed 即可

```
管理端 admin / admin123 登录，供后续发货、关单、退款审核等后台操作使用。
```

### 1.4 停用账号登录失败

**加载场景**：`F01`

```

```

## 四、订单

### 4.1 购物车结算下单

**加载场景**：`S01`

```
客户端 13800000001 登录，从购物车 cartId 5001、5002 结算预览并下单，addressId 4001。核对金额、运费、应付总额；创建成功后能查到待付款订单。
```

### 4.2 直接购买（不经购物车）

**加载场景**：`S07`（已有直接购买待付款单）；或基线后自行直接购买

```
客户端 13800000001 登录，查询场景内待付款订单 orderId 7006（直接购买，payAmount 57），或自行选择 SKU 2101 数量 1、addressId 4001 直接下单，检查金额与订单状态。
```

### 4.3 用券占券的待付款订单

**加载场景**：`S02`

```
客户端 13800000001 登录，查询待付款订单 orderId 7001（payAmount 299，accountCouponId 6001），确认已占用优惠券；查询 accountCouponId 6001 为占券未核销。可选：取消订单 7001 后检查券 orderId 清空、可再次使用。
```

### 4.4 满减门槛不满足

**加载场景**：`F06`

```
客户端 13800000001 登录，购物车 SKU 2101 数量 2 商品总额 98 元未满券门槛，使用 accountCouponId 6001 预览或下单，应失败。
```

### 4.5 余额支付成功

**加载场景**：`S02` 或 `S07`（待付款）

```
客户端 13800000001 登录，对待付款订单（S02 为 orderId 7001，S07 为 orderId 7006）使用余额支付 payType=3，检查订单变为已支付，账户余额相应减少。
```

### 4.6 余额不足支付

**加载场景**：`F07`

```
客户端 13800000002 登录（余额 100），对待付款订单 orderId 7008（payAmount 210）尝试余额支付，应失败，订单仍为待付款。
```

### 4.7 余额不足后充值再支付

**加载场景**：`F07`

```
客户端 13800000002 登录，对 orderId 7008 余额支付失败（余额 100 < payAmount 210）后，模拟充值 amount 200，再次余额支付应成功；查询余额流水，应有充值与支付记录。
```

### 4.8 重复支付拦截

**加载场景**：`S03`

```
客户端 13800000001 登录，对已支付待发货订单 orderId 7002 再次发起支付，应被拒绝。
```

### 4.9 用户取消待付款订单

**加载场景**：`S07`

```
客户端 13800000001 登录，取消待付款订单 orderId 7006，订单变为已取消，占用的库存按规则释放。
```

### 4.10 超库存下单失败

**加载场景**：`F04`

```

### 4.11 越权查看他人订单

**加载场景**：`F09`

```

### 4.12 确认收货

## 十、端到端复合流程

### 10.1 购物流程主链路

**加载场景**：`S01`（流内自行完成支付，无需再切场景）

```
客户端 13800000001 登录 → 查看购物车 cartId 5001/5002 → 结算预览 → 下单 → 余额支付 → 查询订单与个人余额，核对金额与状态一致。
```

### 10.2 下单到退款全链路

**加载场景**：`S03` 申请退款；管理端审核可切 `S06` 或流内连续操作

```
客户端 13800000001 对已支付订单 orderId 7002 申请退款；管理端 admin 审核 refundId 并通过、完成退款；检查余额、订单与退款单状态前后一致。
```

### 10.3 双端协作（发货后不可退）

**加载场景**：`S03` 支付后管理端发货；验证不可退可用 `S04` 或 `F11`

```
客户端 13800000001 对 orderId 7002 完成支付后，管理端 admin 发货；再加载 S04 或 F11，对已发货订单 orderId 7003 或 7011 尝试退款，应不可退。
```

### 10.4 余额不足恢复链路

**加载场景**：`F07`

```
客户端 13800000002：对 orderId 7008 余额支付失败 → 模拟充值 200 → 再支付成功 → 查询流水。不要混入无关步骤。
```
