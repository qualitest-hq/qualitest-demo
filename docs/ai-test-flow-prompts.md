# qualitest-demo AI 测试流自然语言提示集

本文档是 **商城业务提示与测值的单一事实源**。鉴权模板（客户端/管理端 Bearer）**不**内置靶场业务芯片；造流时把本节正文粘贴到画布 AI，或自行在项目里加芯片。

**定位约定**：提示用业务键（订单号、券名、商品/SKU 名、收货人地址等），不要写种子数字主键（`orderId 7002`、`couponId 3002` 等）。主键从列表/新增回执提取后再调改删。金额、数量、状态可写死作断言。场景加载 ID（`S03` / `F07`）保留。

## 使用方式

1. **先挂登录子流**（推荐）：主流 Start 后挂对应端预制登录子流（或项目里已 Apply 的登录流），业务提示**不要再写登录步骤**。托管头用 `{{asset.clientAuth.token}}` / `{{asset.adminAuth.token}}`。
2. **先准备数据（命令优先）**：对提示上方标注的场景 ID，用管理端 Token 调  
   `POST http://localhost:8801/web/test/scenario/load/{场景ID}`（默认先 reset 再写入）。  
   PowerShell / curl 示例见质衡手册 [全面测试手册.md §A.3.1](../../qualitest/docs/全面测试手册.md)。  
   仅 reset：`POST /web/test/scenario/reset`。demo 未起时用 `sql/seed/reset_test_data.bat` + `load_scenario.bat`。  
   demo-ui「测试场景」页可选，**不必为加载而切页**。
3. **再发提示**：把该条的 **加载场景**、**提示正文**（含测值）粘贴到 AI 设计助手；也可用平台造流动词骨架。
4. **AI 负责**：选接口、串联请求、提取变量、设计断言；**不必在提示里写 URL**。
   - 认证专项（测登录本身 / F01 失败）仍可写登录；失败路径用「预期业务拒绝」+ 字面量。
   - 客户端 token 抽取多为 `$.data.token→asset.clientAuth.token`；管理端 `/login` 多为 `$.token→asset.adminAuth.token`。
   - 勿再写「开启会话保持 / useRunSession」（已废弃）。

## 编写原则

| 写入提示正文（AI 测不到） | 交给 AI（不必写死） |
|---|---|
| 加载哪个场景 | HTTP 路径与方法 |
| 业务步骤与业务键（订单号、券名、商品名等；默认已挂登录子流） | 逐步接口调用顺序；从列表提取主键 |
| 停用账号、商品/SKU/券名、库存、余额等预制状态 | 除场景给定外的字段枚举字面量 |

## 十、端到端复合流程

### 10.1 购物流程主链路

**加载场景**：`S01`（流内自行完成支付，无需再切场景）

```
查看购物车「iPhone 壳·透明款」「T 恤·M码白色」→ 用张三默认地址结算预览/下单（预览应付 195）→ 余额支付 payType=3 → 查询订单与个人余额，核对金额与状态一致。
```

### 10.2 下单到退款全链路

**加载场景**：`S03` 申请退款；管理端审核可切 `S06` 或流内连续操作

```
对已支付订单号 MO2026062110100001 申请退款；管理端找到该订单下的退款单审核通过并完成退款；检查余额、订单与退款单状态前后一致。
```

### 10.3 双端协作（发货后不可退）

**加载场景**：`S03` 支付后管理端发货；验证不可退可用 `S04` 或 `F11`

```
对订单号 MO2026062110100001 由管理端发货；再加载 S04 或 F11，对已发货订单号 MO2026062110150001 或 MO2026062111150001 尝试退款，应不可退。
```

### 10.4 余额不足恢复链路

**加载场景**：`F07`

```
辅测号：对订单号 MO2026062111000001 余额支付失败 → 模拟充值 200 → 再支付成功 → 查询流水。不要混入无关步骤。
```
